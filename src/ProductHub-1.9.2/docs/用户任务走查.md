# 用户人物与核心任务走查（v1.1 → v1.2）

方法：为每个人物选出最高频的任务，用 Playwright 脚本在**真实运行的应用**里逐步操作（同一份预置数据，1440×900），统计鼠标点击、文本输入、快捷键的次数，并记录卡点。脚本可复现：
- v1.1 基线：`node scripts/task-walk-v11.mjs`，结果在 `docs/task-walk-v1.1.json`
- v1.2：`node scripts/task-walk-v12.mjs`，结果在 `docs/task-walk-v1.2.json`

## 1. 人物（Personas）

| 人物 | 角色 | 使用频率 | 最关心 | 主要任务 |
|---|---|---|---|---|
| **小林 · 产品经理** | 做竞品分析、写 PRD | 每周数次 | 快速找到同类产品和差异点 | T1 找竞品 / 相似产品 |
| **老周 · 投资研究员** | 跟踪早期项目 | **每天早上** | 今天出现了什么新东西，关注的项目有没有新动作 | T2 每日看新增，T5 关注跟踪 |
| **阿杰 · 数据运营** | 维护监控来源与抓取规则 | 每天 / 出问题时 | 哪些来源坏了，修规则要快 | T3 维护来源和规则 |
| **Mia · 市场分析** | 给团队输出周报 | 每周 | 一键得到能直接分享的报告 | T4 导出报告 |

## 2. 任务走查结果（点击 / 输入 / 快捷键）

| 任务 | v1.1 操作路径 | v1.1 次数 | v1.2 操作路径 | v1.2 次数 | 变化 |
|---|---|---|---|---|---|
| **T1 找竞品**（小林） | 点搜索框 → 输入名称 → 点结果行 → 点「找相似」 | 3 点击 + 1 输入 | `Ctrl+K` → 输入名称 → 选「找『X』的竞品」（同时打开详情和相似列表） | **1 点击** + 1 输入 + 1 快捷键 | −2 点击；在任何页面都能直接发起 |
| **T2 每日看新增**（老周） | 点「最近收录」→ 逐行看日期，**没有“今天新增多少”的答案** | 1 点击 + 人工比对，任务**无法真正完成** | 启动即进入首页：今日 / 近 7 天新增、新增列表、关注动态、来源健康一屏可见 | **0 点击** | 从“做不到”变成“打开即得” |
| **T3 维护失败来源**（阿杰） | 来源监控 → 状态下拉 → 选「失败」→ 行内规则按钮 → AI 生成 → 测试；**失败来源没有任何入口提示** | 6 点击 | 首页「来源异常 48」或状态栏红色提示（列表已自动筛好「失败」）→ 行内规则按钮（同页 Tab）→ AI 生成 → 测试 | **4 点击** | −2 点击；问题被主动推到眼前 |
| **T4 导出报告**（Mia） | 分类下拉 → 选项 → 查询 → 导出 → 格式，再打开分析看板发现**无法导出**，只能得到原始表格（最短路径是侧栏分类 → 导出 → 格式，共 3 次） | 6 点击（最短 3），仍然只有原始数据 | 分析与报告 → 「导出报告（HTML）」，得到带 KPI、分类分布、Top 20 的可分享页面；也可导出 Markdown | **2 点击** | 原始表格变成可直接分享的报告 |
| **T5 关注产品后续**（老周） | **没有收藏 / 关注功能**，无法完成 | — | 点产品 → ☆ 关注 → 回首页即可看到「我的关注 / 有新动态」 | **3 点击**（一次性设置） | 新能力 |

结论：脚本实测的总点击数从 **16 次降到 10 次**（T5 在 v1.1 中无法完成，按 0 计）。v1.1 中有 3 个任务**无法完成或只能部分完成**（T2、T4 报告、T5），v1.2 中全部可完成。

## 3. 走查中发现的摩擦（驱动本次改版）

1. **没有“今天”的概念**：数据只按时间排序，研究员每天要自己比对日期。→ 新建首页，以“首次统计时已有的数据”为基线计算同步新增。离线 / 首次使用时退化为“最近发布”，并明确说明原因。
2. **问题不可见**：48 个来源抓取失败，但界面任何地方都没有提示。→ 状态栏红色计数、首页「来源健康」卡片、侧栏「来源与规则」上的红色徽标，全部一键直达已筛选的列表。
3. **找竞品要先找到产品**：必须先在列表里定位产品。→ 命令面板支持“找 X 的竞品”。
4. **报告 = 原始表格**：导出的 Excel 需要再加工。→ 一键生成 HTML / Markdown 报告。
5. **无法持续跟踪**：→ 关注 + 首页动态。
6. **导航按“功能”而不是按“任务”组织**：来源监控和抓取规则是同一件事却分在两个页面；“工具”分组语义模糊。→ 见下节 IA。
7. **术语不一致**：渠道 / 来源 / 发布渠道混用，分析看板 / 统计 / 报告混用。→ 统一术语表（见使用手册附录）。

## 4. 信息架构调整（IA）

```
v1.1                                v1.2
产品库                               工作台
  全部产品 / 最近收录 / 多次发布 /       首页 · 今日新增      ← 新增，默认启动页
  已 AI 总结 / 手动添加                  产品库
分类（树）                               我的关注            ← 新增
热门标签                             快捷视图（默认折叠）
来源渠道                               最近收录 / 多次发布 / 已 AI 总结 / 手动添加
工具                                 分类（树）· 标签 · 来源
  分析看板                           管理
  来源监控                             来源与规则（Tab：来源列表 / 抓取规则；异常红色徽标）
  抓取规则                             分析与报告（可导出报告）
  导入导出 / 去重                       导入导出
设置                                 设置（+ 重新显示引导）  · 组件库（仅开发模式）
```

- **详情字段优先级**：一句话简介 → AI 总结 → 基本信息（分类、标签、定价、平台、开发者、国家；空字段隐藏）→ 收录情况（发布次数、来源数、票数、首次发布、首次收录、最近出现，6 宫格）→ 详细描述（最多 12 行）→ 备注 → 技术信息（收录方式、GUID、去重键，默认折叠）。
- **列表默认列**：产品（Logo + 名称 + 简介）、分类、标签、发布次数、首次收录、☆。票数（大部分来源没有）和发布日期（与首次收录高度重合）改为可选列；窄窗口时按优先级自动隐藏。
- **命名**：见 `docs/使用手册.md` 附录「术语表」，并由单元测试 `tests/unit/design-system.test.ts` 防止旧称回流。
