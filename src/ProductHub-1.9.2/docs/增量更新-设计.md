# 增量更新设计（v2 · 1.9.0）

装好带全量种子库的桌面端后，用户**不用重装 GB 级的安装包**。客户端会按「数据版本号（seq）」只下载缺少的增量包，在后台合并进本地库。v1 包仍可导入，但只做合并，不推进 seq。

## 1. 包格式 `producthub-delta` v2

文件名形如 `producthub-delta-<from>-<to>.phdelta.json.gz`，gzip 压缩。

```json
{
  "format": "producthub-delta", "version": 2, "dataset": "producthub-main",
  "generated_at": "…",
  "from": { "since": "ISO", "seq": 0, "seed_version": "1.9.0" },
  "to":   { "until": "ISO", "seq": 1, "product_count": 1600000 },
  "counts": { "products": 0, "deleted": 0, "versions": 0, "alt_rel": 0, "alt_rel_deleted": 0, "sources": 0 },
  "checksum": { "algo": "sha256", "body": "sha256(JSON.stringify([products, deleted, alt_rel, alt_rel_deleted, sources]))" },
  "products": [ { "guid": "…", "dedup_key": "host:foo.com", "name": "…", "url": "…", "versions": [ … ] } ],
  "deleted":  [ { "guid": "…", "deleted_at": "…", "merged_into": "保留方 guid（去重合并时）或 null" } ],
  "alt_rel": [ … ], "alt_rel_deleted": [ … ], "sources": [ … ]
}
```

- **products**：自 `since` 以来新增或更新过的产品，附带来源版本。手动产品（manual）不导出。
- **deleted**：删除墓碑，由库里的触发器自动记录。如果是去重合并产生的墓碑，会带 `merged_into`。
- **checksum.body**：正文校验和。校验不通过的包整包拒绝。

## 2. 更新源 `index.json`

```json
{ "format": "producthub-delta-index", "version": 2, "dataset": "producthub-main", "latest_seq": 3,
  "packs": [ { "from_seq": 0, "to_seq": 1, "file": "…gz", "sha256": "…", "size": 123, "products": 60000 }, … ] }
```

客户端按本地 seq 选择补丁链，每一步贪心挑能到达的最大 `to_seq`。有累积包（例如 0→3）时，可以一步跳过中间版本。

## 3. 序号规则

| 情况 | 处理 |
|---|---|
| `to.seq ≤ 本地 seq` | 已应用过，幂等跳过，库不变 |
| `from.seq > 本地 seq` | 缺少中间包，拒绝（`seq-gap`） |
| `from.seq ≤ 本地 < to.seq` | 应用。全部在一个事务里完成，完成后本地 seq = `to.seq` |
| dataset 不一致 / 版本不支持 / 格式错误 / 校验失败 | 拒绝，整体回滚 |

## 4. 下载与合并

- **下载**：先写入 `delta-cache/*.part`，用 HTTP Range 断点续传。完成后校验 sha256 和大小，通过才改名为正式文件，所以不会留下半个包。校验失败会删除临时文件，最多重试 2 次。
- **合并**：在 `worker_threads` 后台线程里执行，主进程 API 和界面不受影响。worker 启动失败时退回主线程合并。合并期间调度器暂停。
- **单事务**：任何错误都会整包回滚；FTS 全文索引在提交后增量同步。
- **用户数据保护**：
  - 收藏、备注、AI 字段、筛选不会被覆盖。
  - 手动产品只补空字段。
  - 被收藏、有备注或手动的产品不会被墓碑删除。
  - 来源的启用状态、抓取间隔和规则保持不变。

## 5. 去重（1.9.0 新增）

入库、增量合并和整库去重共用 `src/server/dedup.ts` 中的同一套规则：

- **R1**：规范化 URL 相同。统一为 https，去掉 www、尾斜杠、默认端口和 index.html，去掉 utm_*、fbclid、gclid、ref、_hs*、mkt_tok 等跟踪参数。
- **R2**：可注册域名相同且名称相同，例如 `app.foo.com` 和 `foo.com`。托管平台（`*.github.io`、`*.vercel.app`、`*.lemonsqueezy.com` 等）按完整子域名判断。
- **R3**：共享域名（github.com、producthunt.com、saashub.com 等）不按域名合并，只按完整路径判断。只有当 GitHub owner 与某个官网域名的主体一致、且名称相同时，才并入那个官网条目。
- **R4**：没有网址的条目（目录站 slug 等），只有在同名候选里只剩唯一一个产品时才并入；有歧义就保留。

**保留哪一条**：手动 > 收藏 > 有备注 > 有网址 > 字段更全 > 发布次数多。两个手动产品之间不合并。

**合并时做什么**：
- 补全空字段，描述取更长的。
- 标签和平台取并集，票数取大值，首次发现时间取最早。
- 来源版本、收藏、备注迁到保留方，alt_rel 重定向到保留方。
- 记录 `product_alias`（旧 guid → 保留方）。以后抓取或增量包再遇到旧 guid，会直接落到保留方，不会再生成重复。
- 被合并方的墓碑带 `merged_into`。客户端收到后，先把本地的收藏和备注迁到保留方，再删除被合并方。

## 6. 发布流程（维护端）

```bash
# 自上一个包的 until 继续出下一个包（可按条数分片）
npx tsx scripts/pack-delta.ts --index data/delta/index.json [--split 60000] [--to-seed 1.9.0]
# 累积包
npx tsx scripts/pack-delta.ts --index data/delta/index.json --cumulative-from 0 --since <ISO>
```

把 `index.json` 和包文件上传到任意静态 HTTP 服务器（需支持 Range），用户在「设置 → 数据更新」里填上更新地址即可。打种子（`npm run pack:seed`）时会把 `index.json` 的 `latest_seq` 写进种子，新装用户直接从最新版本开始。

## 7. 客户端入口

在「设置 → 数据更新」中：

- 显示当前数据版本号和产品数。
- 填写更新地址。
- 「自动检查更新」开关：启动 60 秒后检查一次，之后每 6 小时检查一次；只检查，不自动下载。
- 「检查更新」「下载并更新」「导入本地包」三个按钮，带进度条和结果提示。

API：`GET /api/delta/status`、`GET /api/delta/job`、`POST /api/delta/check`、`POST /api/delta/update`、`POST /api/delta/apply?source=file|url|body`。
