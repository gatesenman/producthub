# 统一产品库 UI / 交互走查报告 v3（v1.2.0 → v1.3.0）

**视角**：资深 UI 设计师 + 交互设计师双视角，逐屏走查 v1.2 截图（`screenshots/v1.2/`）与真实操作流程。保留 shadcn/ui、普通表单查询、任务型信息架构不变，只做“质量层”打磨。
**证据**：
- 修复前截图在 `screenshots/v1.2/`；
- 修复后截图在 `screenshots/`：01–21 与 v1.2 场景一一对应，22–38 为 v1.3 新交互；
- 打包桌面版截图 `screenshots/E1–E6`：在 Xvfb 下运行 `release/linux-unpacked`，E6 用 xdotool 真实点击和按键。
**分级**：P0 阻碍核心任务 / P1 明显影响效率、可达性或理解 / P2 细节打磨。**状态**：✅ 已修复 · 🟡 部分修复 · ⏳ 未修复（附原因）。

## 总体结论

v1.2 的信息架构已经围绕任务组织，但**“做完一件事之后”的体验是薄弱环节**：
- 删除只能靠浏览器原生 confirm，删了也撤不回；
- 列表一次只能操作一个产品；
- 表单出错时只弹一个 Toast，看不出是哪个字段；
- AI 回答要么全有要么全无，中途不能停，出错没有重试；
- 加载失败时页面停在骨架屏上；
- 多组颜色在暗色主题下不满足 WCAG AA。

另外，一个 e2e 用例约 1/6 的概率失败，**根因是一个真实的竞态 Bug**，而不是测试写法的问题。

v1.3 的处理：
- **撤销优先于确认**：删除、取消关注、批量操作都可以在 Toast 里撤销。
- **乐观更新**：先改界面，失败时回滚，并提供「重试」。
- **校验**：全部表单改为内联校验，服务端也做同样的校验。
- **多选与批量操作**：新增多选和批量操作条。
- **键盘可达**：全程可以只用键盘操作。
- **颜色可测**：颜色对比度由单元测试守护。

v2 遗留的 1 个部分修复和 4 个 P2 全部关闭。

## 四、稳定性：e2e 偶发失败（P0，已修复）

- **现象**：用例 8「首页今日新增 + 关注/我的关注 + 列设置」大约每 6 次失败 1 次，常见在重新构建后的第一次运行；报错是 `expect.poll(rows).toBe(1)` 或 `empty-fav` 不可见。
- **排查**：
  1. 先把用例改成自包含：通过 API 创建唯一产品、清空关注、不依赖用例 5 的数据。
  2. 再用 `--repeat-each 15 --retries 0` 单独压测，稳定复现 **6/15** 失败。失败截图显示，在「我的关注」标题下列出了 11–18 个产品，也就是**全部产品**。
- **根因**：这是真实的产品 Bug，不是测试问题。`ProductsView.load()` 没有请求序号守卫。从首页按 Ctrl+3 时，组件挂载会先发出一次“全部产品”查询，紧接着导航 effect 又发出“我的关注”查询。如果前一个响应后返回，就会覆盖列表。用户快速切换视图时也会看到错误的列表。
- **修复**：`load()` 给每次请求编号（`reqSeq`），只有最新一次请求的响应能写入状态；`loading` 和 `loadingMore` 也只由最新请求清除。
- **验证**：
  - 用例 8 单独 `--repeat-each 20` 全部通过（修复前 6/15 失败）。
  - 完整 e2e（17 个用例，`retries: 0`）连续运行 **5 次，全部 17/17 通过**，没有偶发失败。
  - `playwright.config.ts` 的 `retries` 从 1 改回 **0**，不再用重试掩盖问题。
